# droid-config-pdx246

Sailfish OS device configuration for the Sony Xperia 10 VI (pdx246; XQ-ES54 and
XQ-ES72; SM6450 "parrot"), on the Android 16 / LineageOS 23.2 base
(mer-hybris `hybris-23.2`). Unofficial community port, not affiliated with Jolla
or Sony.

It builds `droid-config-pdx246` and its subpackages, the adaptation and
configuration patterns, and the kickstart pieces that turn the image into an
LVM `sailfish.img001` for the userdata partition.

## Layout

Checked out at `$ANDROID_ROOT/hybris/droid-configs`:

| path | what |
|---|---|
| `rpm/droid-config-pdx246.spec` | the spec (`build_packages.sh -c` builds `rpm/droid-config-$DEVICE.spec`) |
| `droid-configs-device/` | submodule mer-hybris/droid-hal-configs at 1dae7f2 (SUBMODULES.md): `droid-configs.inc`, base `sparse/`, `sparse-16/` |
| `patterns/` | adaptation and configuration patterns, generated by `rpm/dhd/helpers/add_new_device.sh` with DEVICE=pdx246 and edited |
| `kickstart/part/pdx246` | root and home file systems (become the LVs `root` and `home`) |
| `kickstart/attachment/pdx246` | the images and flashing files copied next to the image |
| `kickstart/pack/pdx246/hybris` | LVM pack script: `sailfish.img001` and the release zip |
| `out-of-image-files.files` | files of `droid-config-pdx246-out-of-image-files` (flashing, not installed on the phone) |
| `sparse/` | device files, installed over `droid-configs-device/sparse` and `sparse-16` |
| `NOTES.md` | decisions with evidence, TODOs, provenance |

## What sparse/ adds

- Dynamic partitions: `dmsetup-dynparts.service` maps super (slot a) with
  parse-android-dynparts; mount units for `/system_root` (+ `/system` bind),
  `/system_ext`, `/product`, `/vendor`, `/vendor_dlkm`, `/odm`. The other mounts
  are droid-hal-pdx246's units and the vendor init scripts.
- Flashing: `boot/flash-config.sh` (for the generic `flash.sh`),
  `boot/flash-preflight.sh`, `boot/flashing-README.txt`, `flash-partition`
  device-info and the `platform-updates` scripts that update boot_a,
  vendor_boot_a, dtbo_a and vendor_dlkm_a on the phone as one matched set.
- `pdx246-mark-slot.service`: marks slot a successful as soon as the boot HAL
  runs, not only once the UI is up, so failed bring-up boots do not make the
  bootloader fail over to the empty slot b.
- USB (usb-moded on `a600000.dwc3`; the gadget skeleton, and as a bring-up aid
  a forced peripheral mode when no UDC appears within 30 s), ofono binder
  (IRadio 1.5, two slots), mce charging control, connman interface blacklist,
  WLAN start, audio compat link and PulseAudio card options, sensorfw, NFC, CSD
  hardware list, camera labels, ssu community mapping, TrimArea permissions, one
  device-specific disabled Android service.

## Building

1. On the host, in `$ANDROID_ROOT`, with the hybris patches applied:

   ```sh
   export PORT_ARCH=aarch64     # droidmedia's target list depends on it
   source build/envsetup.sh
   lunch lineage_pdx246-bp4a-userdebug
   make hybris-hal droidmedia vendor_dlkmimage audio.hidl_compat.default
   ```

   `audio.hidl_compat.default` is the target of this package's
   `audio.primary.parrot.so` link; without it the link dangles.

2. In the Platform SDK, from `$ANDROID_ROOT`:

   ```sh
   rpm/dhd/helpers/build_packages.sh -d      # droid-hal-pdx246
   rpm/dhd/helpers/build_packages.sh -c      # this repository
   git clone --recurse-submodules https://github.com/mer-hybris/pulseaudio-modules-droid.git hybris/mw/pulseaudio-modules-droid
   git -C hybris/mw/pulseaudio-modules-droid checkout 65edd31f62f22e2eec1f765608ca9c6ae5c4af7b   # 14.2.106
   rpm/dhd/helpers/build_packages.sh -o --mw # default middleware set, offline
   rpm/dhd/helpers/build_packages.sh --mw=https://github.com/sailfish-on-nabu/parse-android-dynparts
   rpm/dhd/helpers/build_packages.sh --mw=https://github.com/sailfishos/sensorfw --spec=rpm/sensorfw-qt5-binder.spec
   rpm/dhd/helpers/build_packages.sh -g      # droidmedia, gst-droid
   rpm/dhd/helpers/build_packages.sh -o -N --mw=droid-hal-img-boot-pdx246
   rpm/dhd/helpers/build_packages.sh -v      # droid-hal-version-pdx246
   rpm/dhd/helpers/build_packages.sh -i      # the image
   ```

   - pulseaudio-modules-droid stays at 14.2.106 (commit 65edd31f), the version
     recommended for Sailfish OS 5.1; newer releases need matching changes in other
     packages. It is cloned and checked out before the middleware run, and `--mw`
     runs with `-o`: without `-o`, buildmw runs `git pull` in every middleware
     repository that already exists, which fails on the detached checkout or moves
     it to a newer release. Missing repositories are still cloned.
   - `-g` packages droidmedia and gst-droid (droidmedia-localbuild from
     `external/droidmedia`); the adaptation pattern requires gstreamer1.0-droid.
     It needs droidmedia from the host build, which is only built with
     `PORT_ARCH=aarch64` set.
   - img-boot is built through `--mw`, not with `-b`: only the `--mw` route runs
     dhd's img-boot preparation, which removes the installed img-boot from the
     build target and installs `droid-hal-pdx246-kernel` and
     `-kernel-modules` again. With `-b`, after a `-d` rebuild the target can keep
     the old img-boot in place of `-kernel-modules` (img-boot Provides and
     Obsoletes it), and the img-boot build finds no modules. `-o` stops `--mw`
     from running `git pull` in the repository, `-N` skips the tag check (the
     repository is untagged; its Version is the kernel version).
   - `-i` makes a `mic create loop` image because the adaptation pattern does not
     require `droid-hal-pdx246-kernel-modules`; the pack script then writes the
     zip with `sailfish.img001`.

## Flashing

`sparse/boot/flashing-README.txt` is the procedure; `flash.sh` runs it. In short:

- Before flashing, LineageOS 23.2 must be installed on slot a and booted once to
  the home screen, then left running for a minute, so that the Virtual A/B merge
  completes.
- Fastbootd first. From the Sony bootloader: the `getvar secure` dry run,
  `fastboot --set-active=a`, `fastboot reboot fastboot`; then
  `./flash-preflight.sh` stops the run unless fastbootd reports current-slot a,
  snapshot-update-status none and is-logical:vendor_dlkm_a yes. From fastbootd:
  `vendor_dlkm_a` and `userdata` (sailfish.img001); `fastboot reboot bootloader`;
  from the bootloader: `boot_a` (hybris-boot.img), `vendor_boot_a`, `dtbo_a`;
  `fastboot --set-active=a`; reboot. Reason: on the first install, recovery_a
  (ramdisk only, it hosts fastbootd) still boots on LineageOS's boot_a kernel and
  vendor_boot_a, which is known to work.
- hybris-boot.img, vendor_boot.img, dtbo.img and vendor_dlkm.img are one matched
  set from one Sailfish OS build.
- Re-flashing over an installed Sailfish OS: fastbootd then runs on the Sailfish
  OS kernel. If `fastboot reboot fastboot` does not reach fastbootd, flash the
  saved LineageOS boot_a, vendor_boot_a and dtbo_a from the bootloader first, then
  run `./flash.sh` again.
- If `flash.sh` stops halfway (USB drop): reconnect until `fastboot devices`
  lists the phone, run `fastboot reboot bootloader`, and start `./flash.sh` again.
- Slot b holds no bootable LineageOS (Virtual A/B keeps one copy of the dynamic
  partitions); rolling back means reflashing the saved slot-a LineageOS set.
