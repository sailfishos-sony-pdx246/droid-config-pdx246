# droid-config-pdx246

Sailfish OS device configuration for the Sony Xperia 10 VI (pdx246; XQ-ES54 and
XQ-ES72; SM6450 "parrot"), on the Android 16 / LineageOS 23.2 base
(mer-hybris `hybris-23.2`). Unofficial community port, not affiliated with Jolla
or Sony.

It builds `droid-config-pdx246` and its subpackages, the adaptation and
configuration patterns, and the kickstart pieces that turn the image into an
LVM `sailfish.img001` for the userdata partition. Building and installing the
port are described in [main](https://github.com/sailfishos-sony-pdx246/main):
`BUILD.md` (this repository is its step `c`) and `INSTALL.md`.

## Layout

Checked out at `$ANDROID_ROOT/hybris/droid-configs`:

| path | what |
|---|---|
| `rpm/droid-config-pdx246.spec` | the spec (`build_packages.sh -c` builds `rpm/droid-config-$DEVICE.spec`), including the `-waydroid` subpackage |
| `droid-configs-device/` | submodule mer-hybris/droid-hal-configs: `droid-configs.inc`, the base `sparse/` and `sparse-16/`, the pattern templates, the generic `flash.sh` |
| `patterns/` | adaptation and configuration patterns, generated by `rpm/dhd/helpers/add_new_device.sh` with DEVICE=pdx246 and edited |
| `kickstart/part/pdx246` | root and home file systems (become the LVs `root` and `home`) |
| `kickstart/attachment/pdx246` | the images and flashing files copied next to the image |
| `kickstart/pack/pdx246/hybris` | LVM pack script: `sailfish.img001` and the release zip |
| `out-of-image-files.files` | files of `droid-config-pdx246-out-of-image-files` (flashing, not installed on the phone) |
| `packaged-in-main-spec.files` | files of `sparse/` that the spec packages itself (`-waydroid`), so that droid-configs.inc leaves them out of `droid-config-pdx246` |
| `delete_file_pdx246.list` | files of the base configuration removed from the image (dummy_netd's AIDL-only configuration: this vendor's netmgrd needs HIDL netd) |
| `sparse/` | device files, installed over `droid-configs-device/sparse` and `sparse-16` |

## What sparse/ adds

- **Partitions:** `dmsetup-dynparts.service` maps the slot-a logical partitions of
  super with parse-android-dynparts; mount units for `/system_root` (+ `/system`
  bind), `/system_ext`, `/product`, `/vendor`, `/vendor_dlkm`, `/odm`. The other
  mounts are droid-hal-pdx246's units and the vendor init scripts. udev rules add
  `/dev/block/by-name` links for the UFS partitions (the boot HAL and apexd look
  partitions up there) and give Sony's tad access to the TA partition.
- **Android 16 under hybris** (`usr/libexec/droid-hybris/system/etc/init/`): the
  image runs with SELinux disabled, so Android's service managers get
  libselinux_stubs preloaded; odsign is stubbed and its properties are set, so
  that init's queue does not wait for it; the APEX BoringSSL self-tests run
  without `reboot_on_failure`; Android services that fail or are not used under
  Sailfish OS are stubbed (`disabled_services_device.rc`).
  `/etc/task_profiles.json` is Android's (logd needs it).
- **Slot marking:** `pdx246-mark-slot.service` marks slot a successful as soon as
  the boot HAL runs, not only once the UI is up, so boots that fail before the UI
  do not make the bootloader fall back to slot b, which holds no system.
- **USB** (usb-moded on `a600000.dwc3`): the configfs gadget skeleton that
  Android's init would create, MaxPower 900 for charging from a PC, high speed for
  MTP, Jolla's vendor ID, a PC told from a USB-PD wall charger by the gadget's
  enumeration (`android_tracking`, no extcon tracking), usb-moded held back until
  the charger's power supply exists, a connman firewall rule for SSH and DHCP on
  usb0, and Android's usbd and QTI gadget HAL stubbed.
- **Telephony:** the oFono binder plugin on IRadio 1.5 with both slots and the
  network scan; the adaptation pattern adds the AIDL IMS client (VoLTE, SMS over
  IMS).
- **Audio:** `audio.primary.parrot.so` links to Halium's
  `audio.hidl_compat.default.so`, so that PulseAudio reaches the vendor's audio
  service through the hybris libhardware; the PulseAudio card options (the
  vendor's audio policy path, volume in PulseAudio, `unload_call_exit`), the qti
  passthrough for call audio, and a start timeout for the system PulseAudio.
- **Power and display:** mce waits for the panel backlight; the charging limit
  from Settings goes through `/run/pdx246-charging-control` to Sony's
  `smart_charging_interruption` node, which appears only once the ADSP runs; for
  the unlock screen of the home encryption, mce stops Android's display composer,
  which holds DRM master (`60-compositor-pdx246.ini`, `pdx246-hwc-control.sh`).
- **Network, sensors, NFC:** connman's interface blacklist, the WLAN start,
  sensorfw waiting for the AIDL sensors HAL, NFC-A/B polling.
- **Other:** the CSD hardware list, the camera labels, the ssu community board
  mapping.
- **Flashing and kernel updates:** `boot/flash-config.sh` (the steps for
  droid-hal-configs' `flash.sh`: fastbootd first, slot a only),
  `boot/flash-preflight.sh` and `boot/flashing-README.txt`, which go into the
  release zip; the `flash-partition` device-info and the `platform-updates`
  scripts that write boot_a, vendor_boot_a, dtbo_a and vendor_dlkm_a on the phone
  as one matched set when the kernel packages are upgraded
  (`flash-recoveryimg.sh` does nothing: hybris-recovery.img is a debug image and
  must not reach recovery_a).
- **Waydroid** (`droid-config-pdx246-waydroid`): the container's own view of
  `/vendor`, without the vendor's copies of libraries that the Android 13 image
  ships itself; links to the container's binder nodes; a check before every
  container start that keeps it off the phone's own binder; and a mask for the
  `lxc@multi-user.service` instance that the lxc package would start (and fail)
  at every boot.

## Updating the droid-hal-configs submodule

After moving the submodule, re-check `sparse-16/`: it is installed as a whole,
and this repository relies on its `disabled_services.rc`,
`droid-bootctl.service` and `droid-bootctl.sh` (also run by
`pdx246-mark-slot.service`), `wait_for_keymint`, `gbinder.conf` (ApiLevel 36)
and `dual-sim.conf`. Re-check the two pattern templates as well, and the
file-splitting rules of `droid-configs.inc` (paths containing `pulse`,
`/dconf/db/`, `flash-partition` or `platform-updates` go to subpackages).
